ASTRYM — модульный инструмент для разведки по открытым источникам. Работает локально, не отправляет данные наружу, покрывает 80% задач без API-ключей. Всё, что находит — складывает в единый граф связей SQLite и умеет выгружать в STIX 2.1, XLSX и Obsidian. Работает офлайн: ASN, geo и MAC-вендор берутся из локальных баз, если API недоступны.

$ python astrym.py ip 8.8.8.8

Почему всё это

ASTRYM появился 1 июня 2026 как один файл на 1400 строк.

Идея была простая: не делать ещё один «список сервисов для OSINT», а собрать один инструмент, который умеет запускать всё локально, складывать данные в единую базу и искать связи.

Отсюда — граф (SQLite вместо заметок), кэш (чтобы API не дёргались по десять раз), экспорт (STIX/MISP/OpenCTI).

Никаких облаков, никаких «мы храним ваши сканы у себя». Всё в ~/.astrym/, всё на твоей машине.

01

Что это

3 принципа

Только открытые источники. Никаких взломов, никаких баз «на продажу». Всё, что собирается, доступно любому человеку в интернете — вопрос только в том, чтобы собрать это за один раз, а не за сто вкладок.

Пассивный сбор где возможно. CT-логи, RDAP, passive DNS, публичные blocklist'ы, HIBP через k-anonymity. Активные запросы — только там, где это осмысленно.

Единый граф. Каждая команда складывает узлы и рёбра в SQLite. Домен, IP, NS, MX, ASN, сертификат — точки в графе. related, correlate, community, path, bridge дают то, ради чего всё и строилось: связи.

Без ключей

CT (crt.sh + certspotter + hackertarget + grepular), RDAP, passive DNS, XposedOrNot, Hudson Rock, IPsum, Spamhaus DROP, Team Cymru, Shodan InternetDB.

С ключами

VirusTotal, Shodan, Censys, SecurityTrails, Hunter.io, MISP, OpenCTI, Jira, Linear, IntelX, HIBP. Через ~/.astrym/config.json.

Экспорт

JSON, HTML, MD, CSV, XLSX, PDF, STIX 2.1, GEXF, Neo4j-Cypher, Obsidian vault. Плюс push в MISP и OpenCTI.

Автоматика

schedule (cron + alert-on), monitor, alerts (Telegram/Discord/webhook), search (FTS5), diff между JSON-сканами.

Чтение вывода

реальные примеры отчётов

Каждая команда печатает структурированный отчёт. Ниже — как он выглядит в консоли, в браузере (HTML), в Excel (XLSX), в Obsidian/Markdown и в виде графа связей. Всё показано на одном реальном примере: astrym.py ip 8.8.8.8 -x.

Цветовая легенда

[+] okвсё хорошо: чисто, валидно, найдено
[!] warnобрати внимание: подозрительно, но не критично
[-] errопасно: malicious, expired, listed, breach
. infoнейтральное сообщение, детали
grey textmuted, служебное, не главное

Риск-скор в check

В конце check печатается строка Score: 45/100 · HIGH. Значение — сумма баллов от источников: VT даёт до 60, Feodo — 25, GreyNoise-malicious — 20, Spamhaus DROP — 20, URLhaus — 25. Каждый источник даёт баллы только если что-то нашёл.

  • 0 — CLEAN, ничего не найдено.
  • 1–15 — LOW, единичные совпадения.
  • 15–40 — MEDIUM, 3+ движка или blocklist.
  • 40–70 — HIGH, серьёзные источники (Feodo, Spamhaus DROP, OTX).
  • 70+ — CRITICAL, активная malware-инфраструктура.

Консенсус в ip и domain

Несколько источников (ip-api, ipwho, ipinfo, RIPE, Team Cymru) отвечают про страну/ASN/ISP. Консенсус считает голоса и помечает поле:

  • confirmed (4/4) — все согласны, можно верить.
  • likely (2/2) — большинство согласно.
  • single (1/1) — только один источник ответил.
  • weak (1/2) — источники разошлись.
  • conflict — полное расхождение, смотри поле alternatives.
AnycastДля публичных DNS (8.8.8.8, 1.1.1.1) страна/город/таймзона помечаются как anycast, а не conflict — потому что один IP действительно живёт в десятке стран одновременно.

Интерактивная версия умеет больше: клик по узлу открывает панель справа с путём от target, списком строгих/мягких/слабых связей, мини-графом и raw JSON. Тулбар справа внизу — экспорт PNG/SVG, highlight соседей, фильтр по типам узлов. Горячие клавиши: Ctrl+H — highlight, Ctrl+E — PNG.

Как читать граф

  • related github.com --depth 2 — что привязано к github.com на 2 шага вглубь.
  • path a b — путь между узлами. Сначала прямой, потом soft bridge через общий узел.
  • bridge a b — что общего: общий ASN, NS, certificate issuer.
  • community — Louvain-сообщества. Modularity > 0.4 — есть структура.
СоветГраф наполняется при каждом запуске ip, domain, sub, check, ssl, web, takeover, hr-*, identity, wmn. Через 20–30 целей community начинает показывать рабочие кластеры.
02c

Obsidian

перенос результатов в граф знаний

Obsidian — бесплатное приложение для заметок в формате Markdown с поддержкой [[wikilinks]]. ASTRYM выгружает любой скан в готовый vault — набор связанных заметок, которые Obsidian сразу понимает.

Зачем это нужно: можно собрать базу по клиенту или проекту, где каждое сканирование — отдельная заметка, а домены, IP и почты связаны между собой. Obsidian сам покажет граф связей и даст поиск по всему vault.

Что происходит при выгрузке

Запуск с флагом obsidian

Любая команда может выгрузить в Obsidian-формат. Можно комбинировать с другими через запятую.

python astrym.py domain github.com -f obsidian
python astrym.py domain github.com -f json,html,obsidian

Создаётся папка _obsidian

Рядом с остальными результатами появится папка с суффиксом _obsidian. Это и есть vault — папка с .md-заметками.

results/domain/domain1_obsidian/

Внутри — связанные заметки

Каждая секция скана становится отдельной заметкой: DNS, WHOIS, субдомены, security, extended. Плюс — index.md как оглавление и <target>.md как заметка цели.

Ссылки [[...]] связывают заметки

Каждый домен, IP, NS в отчёте превращается в [[wikilink]]. Obsidian видит это как связь: открываешь github.com → сразу видно, куда ещё он ведёт.

Открываешь папку в Obsidian

В Obsidian: Open folder as vault → выбрать results/domain/domain1_obsidian/. Всё, ты внутри.

Смотришь граф

Горячая клавиша Ctrl+G (или иконка graph) — увидишь узлы и связи между заметками. Это локальный граф в Obsidian, независимый от SQLite-графа ASTRYM.

Структура vault · пример

domain1_obsidian/ ├── index.md ← оглавление: ссылки на все заметки vault ├── _overview.md ← главная заметка: тип, дата, риск, ссылки на секции ├── github.com.md ← заметка цели: [[api.github.com]], [[gist.github.com]], ... ├── dns.md ← DNS: A/AAAA/MX/NS/TXT, таблица ├── whois.md ← WHOIS: registrar, created, expires ├── subdomains.md ← субдомены как [[wikilinks]] ├── security.md ← risk level + score + reasons + источники └── extended.md ← extended sources: certspotter, hackertarget, ...

Что писать в какую заметку

ЗаметкаКогда появляется и что внутри
index.mdВсегда. Оглавление vault: список секций, ссылка на _overview.
_overview.mdВсегда. Тип скана, дата, уровень риска (если есть), список доступных секций.
<target>.mdВсегда. Отдельная заметка цели — чтобы Obsidian показывал backlinks: кто ещё ссылается на этот домен.
dns.mdЕсли были DNS-записи. Таблица по типам A/AAAA/MX/NS/TXT/CNAME.
whois.mdЕсли есть WHOIS. Таблица registrar / creation date / expiry / NS.
subdomains.mdЕсли есть субдомены (CT или sub-скан). Таблица host / sources.
security.mdЕсли есть risk или security-блок. Level, score, все reasons, разбивка по источникам.
extended.mdЕсли были extended-источники (-x). Секция по каждому источнику + ссылки на внешние сервисы.
hudsonrock.mdДля hr-email, hr-username, hr-domain. Таблица stealers / employees.
identity.mdДля identity. Секции emails / phones / usernames / leaks / stealers / wmn.
wmn.mdДля wmn. Список найденных сайтов, каждый — ссылка.
leakcheck.mdДля leakcheck. Источники + поля.
email_full.mdДля email-full. Сводка по всем leak-источникам.

Куда идти дальше в Obsidian

Graph view. Ctrl+G — граф всех заметок и их связей. Если в vault много субдоменов, картинка становится интересной. Хорошо для презентации клиенту.

Backlinks. Открываешь github.com.md — в правой панели видишь, кто ссылается на эту заметку. Это все домены, где упомянут github.com как субдомен или NS.

Search. Ctrl+Shift+F — полнотекстовый поиск по всему vault. Работает быстрее, чем astrym search, потому что это локальный Markdown.

Tags. В frontmatter каждой заметки есть tags: [astrym, osint, domain]. Можно фильтровать по ним: показать все заметки с тегом phishing (это те, где risk: phishing).

Совмещение с остальными форматами

Obsidian не заменяет остальные форматы, а дополняет их. Рабочая связка:

  • -f json — сырые данные, скормить другой утилите или в CI.
  • -f html — открыть в браузере, показать коллеге.
  • -f xlsx — Excel/Sheets, если нужно передать таблицу.
  • -f obsidian — долговременное хранение в базе знаний.

Всё вместе: -f json,html,xlsx,obsidian — получишь четыре представления одного скана.

Roadmap

без дат

Не «Q1 2027», а просто список. Что-то сделано, что-то в работе, что-то отложено — и это честно.

готово

XLSX с фиксированной структурой

01_summary, 02_key_data, 03_consensus с цветом, секционные 04_*, 99_raw, !failed. Env-флаги для отключения raw и цвета.

готово

Параллельный extended-сбор

_x_ip — 6 источников через ThreadPool, таймаут 5с, общий cap 10с. Команда ip -x завершается за 5-6 секунд вместо 40. team_cymru заменён на RIPE Stat.

готово

extended._failed

Короткий список упавших источников в JSON, подробно в консоли. Виден в xlsx листом !failed и в HTML отдельным блоком.

готово

Реальные превью отчётов на сайте

Раздел «Чтение вывода» содержит консольный вывод, HTML-карточки с тулбаром, XLSX-вкладки, Markdown с frontmatter и статичный снимок topology.

готово

Lazy import для CLI

Старт занимает ~900 мс — почти всё это импорт тяжёлых модулей (networkx, reportlab, phonenumbers), которые не нужны для 90% команд. Lazy import ускоряет astrym.py --help до ~200 мс.

готово

ProcessPool через диспетчер без лямбд

Module-level диспетчер _r2_run_task — threat intel идёт через ProcessPool с настоящим жёстким таймаутом, а не через threads-fallback.

готово

Workspaces в SQLite-графе

--ws client1 открывает отдельную БД ws_client1.db. «Работа» и «личные сканы» больше не мешаются в одном графе.

готово

Rate-limit в serve.py по IP

Token bucket на 60 rps + отдельный на /batch. Возвращает 429 с Retry-After, учитывает X-Forwarded-For.

готово

PDF-реанимация

Reportlab с авто-TTF, fallback на fpdf2. pdf-status показывает, что реально работает на текущей машине.

готово

Schedule API с alert_on из CLI

schedule-add --cron "0 6 * * *" --alert-on new-subdomain,ip-change. Плюс schedule-run --due для внешнего crontab.

готово

Hudson Rock rate-limit handling

Retry при 429 с учётом Retry-After. Кэш успешных ответов на 24 часа. hr-status — счётчики за сессию.

готово

XLSX / Neo4j / Obsidian для новых команд

XLSX-листы hr_stealers, identity_*, wmn_found. HTML-рендеры для 14 новых типов. Obsidian-заметки.

готово

WMN 500+ сайтов параллельно

Thread-local sessions, 40 воркеров по умолчанию, прогресс, статус unknown для 403. ASTRYM_WMN_WORKERS для подкрутки.

07

Что не попало

сознательно

Честный список «почему нет» важнее списка «что есть». Всё это — вещи, которые кто-то просил, но мы решили не делать.

Скрейпинг соцсетей

Instagram, VK, Facebook — требуют auth, ломаются еженедельно, тянут за собой вопросы ответственности. Оставили только публичные ссылки на страницы через Google Dorks.

Пробив по номеру через боты

Платные Telegram-боты «дай номер — верну ФИО» — это не OSINT, а покупка чужих данных. Ни при каких условиях.

Показ паролей из утечек

Есть Hudson Rock — он показывает факт заражения и семейство stealer'а. Сами пароли в CLI не выводим: слишком легко превращается в инструмент шантажа.

Деанон по фото / лицу

Поиск по лицу через публичные сервисы — этически серая зона. Плюс точность 50/50, ложные срабатывания разрушают репутацию сильнее, чем помогают.

Брутфорс логинов / админок

Это уже не разведка, а атака. ASTRYM — про наблюдение, а не про вторжение.

Обход капчи

Ломает чужие сервисы, нарушает ToS, и создаёт нагрузку на публичные API, от которых мы же и зависим. Если сайт ставит капчу — уважаем.

Автопокупка «баз» за крипту

Нет. Ни в каком виде. Ни через API, ни через парсинг закрытых каналов.

Мониторинг конкретного человека без его ведома

Инструмент для инфраструктурной разведки (домены, IP, ASN, сертификаты). Мониторинг живого человека на постоянной основе — вне области проекта.

07b

Локальные базы

офлайн-режим

ASTRYM работает без интернета: ASN, страна, город, вендор по MAC и гео берутся из локальных баз. Если API недоступны — команда ip переключается на локальные источники. Команды ip-local и mac работают офлайн всегда.

Все базы — открытые: RIR, IEEE OUI, MaxMind GeoLite2, DB-IP Lite, iptoasn, ip2region, oui-master, as-ip-blocks. Никаких сливов и коммерческих API.

Установка

Python 3.10+

Скачай папку astrym/, поставь зависимости, запусти.

# 1. зависимости pip install requests dnspython rich networkx reportlab phonenumbers pycountry openpyxl pyexiftool # 2. конфиг (по желанию) mkdir -p ~/.astrym nano ~/.astrym/config.json # 3. локальные базы (офлайн-режим, ~319 MB) python astrym.py db-sync # 4. запуск python astrym.py help python astrym.py domain github.com -x

Зависимости опциональны. Без ключей работает всё, кроме VT / Shodan / Censys / SecurityTrails / Hunter / MISP / OpenCTI / Jira / Linear. Без dnspython часть DNS отваливается, без rich — цвета, без networkx — community / gexf.

Termux на Android. Зависимости через pip, exiftool — через pkg install exiftool. Рабочая папка по умолчанию /storage/emulated/0/astrym/, конфиг в ~/.astrym/.
